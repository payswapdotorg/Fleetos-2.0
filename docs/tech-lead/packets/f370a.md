## Deliverables (all in your owned paths)

1. **Credential verification** (`packages/identity/src/credentials.ts`):
   - `issueCredential` / `verifyCredential` over a frozen credential record
     (actorId, tenantId, kind) with a salted hash (node:crypto `scrypt` —
     deterministic parameters, no external dependency);
   - plaintext NEVER stored, NEVER logged, NEVER echoed in errors;
   - timing-safe comparison (`crypto.timingSafeEqual`) on the digest;
   - unknown-actor and malformed-credential refusals are
     indistinguishable (no user enumeration).
2. **Signed session tokens** (`packages/identity/src/session.ts`):
   - `issueSession` / `verifySession`: HMAC-SHA256 over the frozen claims
     (actorId, tenantId, scopes, issuedAt, expiresAt) with a caller-supplied
     key (the pilot key is a fixture, plainly labelled — real secret
     management is F370B/later, recorded honestly);
   - tamper refusal (any claim mutated → REFUSED), expiry refusal,
     wrong-key refusal; verify is total (never throws, always a verdict).
3. **The authorization gate** (`packages/identity/src/marketplace-gate.ts`):
   - `authorizeMarketplaceAction(session, action)` composing
     `verifySession` + the actor→tenant binding + the action-scope table
     (request/offer/comparison/order/ack/receipt/enrollment/approval —
     the F360 §3 frozen verbs);
   - verdicts: `AUTHORIZED {actorId, tenantId, action}` or
     `REFUSED {reason}` with the frozen reason codes
     (UNAUTHENTICATED / SESSION_EXPIRED / TENANT_MISMATCH / SCOPE_MISSING /
     MALFORMED) — REASONS ARE DATA, never exception control flow;
   - fail-closed default: anything not exactly authorized is refused.
4. **The authenticated marketplace composition**
   (`packages/identity/src/marketplace-authenticated.ts`): the REAL public
   APIs of the Wave-17 lanes (the F361C request/offer/order surfaces, the
   F361A receipt/enrollment surfaces, the F361B Guardian approval surface)
   COMPOSED behind the gate — the gate authenticates + authorizes, then
   delegates to the EXISTING kernels verbatim. NEVER re-implement a domain
   behavior; NEVER edit the domain packages (a composition that seems to
   need an edit is a FINDING for your report, not an edit).
5. **D14 journeys** (`packages/acceptance/security/src/journeys/`): >=4
   census-certified journeys driving the authenticated composition
   end-to-end — happy path per verb family + >=1 refusal at EVERY gate
   (unauthenticated call, expired session, tampered token, cross-tenant
   read on >=3 surfaces, scope-missing action, credential verification
   failure with enumeration-resistance asserted).
6. **Evidence** (`docs/evidence/F370A/report.md`): census grep proofs at
   base, contract surface file:line, journey table with per-journey
   refusal paths, suite counts, honest limitations (the fixture key, the
   actor convention retired ONLY at the authenticated boundary — the pure
   domain kernels keep their tested shape).
