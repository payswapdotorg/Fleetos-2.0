## Deliverables (all five packages; keep exports additive, never break existing public shapes)

### packages/workloads — the allocation engine at truth grade
- Allocation lifecycle: proposed → committed → active → released/retired with legal-transition enforcement and rejection codes.
- Deterministic capacity accounting: allocate/release keep utilization invariants (never over-commit beyond capacity; release restores exactly).
- Workload scheduling windows (start/end ordering validity, overlap detection with deterministic tie-breaks).
- Idempotent re-apply of an allocation demand (same key → same result, no double-commit).

### packages/projects — project lifecycle + accounting at truth grade
- Project/stage state machine with stage gates (a stage cannot close with open mandatory checkpoints; rejection codes).
- Budget envelope + actuals ledger: deterministic accounting, budget-breach detection with severity, append-only entries with audit digests.
- Tenant fail-closed reads; project archival rules.

### packages/procurement — the full procure-to-receive flow
- Need → Demand → Quote → Order → Fulfillment state machine with approval gates at Demand→Quote (solicitation) and Quote→Order (award): evidence/authorization refs required, rejection codes for every illegal transition.
- Quote comparison: deterministic scoring (price, terms, vendor capability match) with documented tie-breaks; no floats in decision outputs (basis-point integers or similar).
- Order totals reconciliation: received vs ordered with variance classification.
- Idempotent document creation (client-supplied request ids).

### packages/vendors — vendor lifecycle + capability catalog
- Vendor lifecycle: prospective → active → suspended → terminated with reinstatement rules and reason codes.
- Capability catalog: declared vs verified capabilities (verification requires evidence ref).
- Performance records: deterministic KPI rollups from fulfillment outcomes (on-time ratio as integer basis points, etc.).
- Service relationship lifecycle with exposure limits.

### packages/software — catalog + entitlements
- Software catalog entries with version lifecycle (registered → deprecated → retired).
- Entitlement grant lifecycle: granted → assigned → expired/revoked with seat-count invariants (never over-assign).
- License compliance checks: deterministic rule evaluation with rejection codes.
