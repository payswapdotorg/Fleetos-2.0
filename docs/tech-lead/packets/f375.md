# F375 — FleetOS Desktop for Ubuntu (the installable product app)

## Mission

The operator's direct product order (2026-10-16, live word): **"Make sure
there's a downloadable desktop app my local agent can install on my Ubuntu
desktop. The app should be the product we're building and not zcode."**

FleetOS — the company IT-equipment marketplace — exists today as the shell
(`packages/web`, the F301 standalone build: `fleetos.html` -> `dist-fleetos/`,
hash routing, static-servable, composes the REAL FleetOS domain packages
in-browser) over the local services (the durable deployment service at
:3106 — the F351A composition; the marketplace store; the KMS daemon). This
lane packages THAT product as a real installable Ubuntu desktop app:

- an **Electron** desktop app (new package `packages/desktop`) whose main
  process boots the durable deployment service (compose the existing
  `infrastructure/fleetos-durable` service code — NEVER a reimplementation)
  on `127.0.0.1:3106` (the shell's frozen durable-mode port), serves the
  built FleetOS shell from the app resources, and opens the product window
  ("FleetOS", product branding);
- packaged with **electron-builder** as a **`.deb`** (`fleetos_2.0.0_amd64.deb`
  — installable on Ubuntu with `sudo apt install ./fleetos_2.0.0_amd64.deb`
  or `sudo dpkg -i`) + an **AppImage** (`FleetOS-2.0.0.AppImage`, portable);
  the .deb installs `/opt/FleetOS`, an XDG `.desktop` entry (the app appears
  in the Ubuntu application grid with the FleetOS name + icon), and a
  `fleetos` command;
- **the app is the PRODUCT**: the FleetOS shell + the local FleetOS services
  ONLY. ZERO replay/console/agent tooling ships in it. (The monorepo's
  `@zcode/*` workspace deps are the shared UI/component toolkit the shell
  builds against — they are build inputs, not shipped agent tooling; the
  built artifact is the FleetOS product surface.)

The desktop artifact is the product's honest form: the same fixture-labelled
demo world the shell demonstrates (the F351A composition), never the
live-pilot (that gate stays BLOCKED on F369/F371), the same durable
write-before-ack/replay-on-start/idempotency laws machine-proven at F351A.
