## Procedure

1. Branch `work/f310a` from the actual current `main` HEAD. Record the SHA.
2. If the typecheck fails with REAL TypeScript errors (not OOM):
   - errors inside **your owned paths** (worker-a list in
     `spec/worker-ownership.yaml`): fix them minimally and truthfully;
   - errors in **TL-owned or substrate paths**: do NOT patch them — produce a
     minimal reproduction and a scoped repair proposal in your report.
   - NEVER loosen compiler options, add `@ts-ignore`-style suppressions, or
     edit tsconfig merely to force green. The handoff forbids it.
3. Push `work/f310a`. The CI run starts automatically at your exact commit.
4. Capture from the run: the run URL + run ID, the `root-typecheck` job's
   conclusion, exit code, the builder-facts block, and the typecheck log
   (artifacts are attached to the run).
5. Write `docs/evidence/F310A/report.md`:
   - exact tested SHA + branch;
   - builder facts (RAM/CPU/node/pnpm/runner image) proving the ≥8GB class;
   - the command, its exit code, and the machine output (quote the tail);
   - run URL (public, permanent);
   - any real failures found + repairs (owned) / repair proposals (not owned);
   - explicit statement: B-1 CLOSED at this SHA, or B-1 remains OPEN with
     reproduction and repair path.
6. Commit your evidence to `work/f310a` and push. Final message:
   **"FINAL REPORT"** with the SHA, run URL, exit code, and B-1 status.
