## Objective — make the org machinery INDUSTRY-SPECIFIC and machine-optimizable

The `agent-organizations` package already owns roles, budgets, role allocation, routing optimization and what-if analysis as generic machinery. Wave 9 makes it industry-concrete: **industry archetypes** (role topologies, budget envelopes, routing objectives per industry + org size tier) and **per-industry optimization** wired into the EXISTING seams. All work is IN your existing packages (new `industries/` modules inside `packages/agent-organizations` are the natural home), never new top-level packages.

### Deliverables — all pure deterministic TS; logical `now`/caller-supplied inputs everywhere

1. **Industry archetype registry** (`packages/agent-organizations/src/industries/archetypes.ts`): ≥ 6 industries (e.g. manufacturing, logistics, energy-utilities, facilities, field-services, construction) each defining: role topology (a REAL `AgentRoleDefinition` set sized by org tier — small/medium/large), capability budget envelope policy per tier, routing objective weights (cost vs latency vs quality tradeoffs as explicit weights), and an honest `industryAssumptions` note field. Archetypes are DATA + pure constructors over the existing contracts — do not fork the machinery.
2. **Industry fit scoring** (`packages/agent-organizations/src/industries/fit.ts`): deterministic rubric scoring a tenant profile (sector signal, fleet size, workload mix — caller-supplied data, no imports outside your lane) against each archetype; ranked output with score components (the rubric is explainable: each component's contribution is in the result); ties resolved deterministically.
3. **Per-industry optimization policies** (`packages/agent-organizations/src/industries/optimization.ts`): for each archetype, a policy object driving the EXISTING `role-allocator`, `routing-optimizer` and `budget-rebalancer` seams (weights, envelopes, ladder preferences — policy DATA feeding the existing functions, not replacements); industry-mismatched policies (e.g. an energy envelope applied to a manufacturing org config) must be refused or warned with REAL reason codes — pick one, test it, document it.
4. **Org optimization benchmark** (`packages/agent-organizations/src/industries/benchmark.ts`): deterministic benchmark that instantiates an archetype org, runs it through allocation → routing → rebalancing over scenario loads (per industry), and reports per-industry scores with **improvement-vs-generic-baseline assertions** (the industry policy must measurably beat the generic default on the industry's own objective — tested, with the delta in the benchmark result); plus a **byte-identical determinism proof** (re-run → same digest).
5. **Model-gateway capability matching** (`packages/model-gateway` — small extension only): map industry skill requirements (from the archetype) to model-option capability tags through the gateway's EXISTING public surfaces; unmatched requirements are honest refusals with reason codes.
6. **Tests ≥ 60 net-new**: archetype validity (every role/budget/routing artifact passes the EXISTING validators); fit-scoring rankings incl. tie fixtures; optimization-policy refusals; benchmark improvements actually asserted; determinism proofs; cross-tenant probes fail closed.
