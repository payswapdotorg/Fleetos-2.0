### Deliverables — all pure deterministic TS; logical `now`/caller-supplied inputs everywhere

1. **`src/industries.ts`** — TEN industry definitions as DATA (typed `IndustryDefinition`):
   manufacturing, construction, energy-utilities, transportation-logistics,
   agriculture, healthcare-facilities, facilities-management,
   telecommunications, mining, water-waste. Each carries: stable id, display
   name, asset-profile mix (heavy-equipment / vehicle / fixed-asset /
   instrument weights as integers), posture emphasis (connectivity-edge vs
   security-intelligence vs work-commerce), incumbent capability baseline
   (see deliverable 4), and applicability masks over the three corpora's
   journey ids (which journeys are industry-applicable — an honest subset,
   not all-42 for everyone; e.g. agriculture leans field+commerce and masks
   counterfactual? — you decide from the journey semantics; document the
   rationale per masked journey in the evidence report).
2. **`src/firms.ts`** — firm sizing + the 30-workspace population:
   `FirmSize` = small | medium | large (typed). For EACH industry, exactly 3
   firms (one per size) = 30 firm workspaces. Each `FirmWorkspace` carries:
   stable id, industry id, size, a REAL per-firm tenant id (derived
   deterministically, e.g. `tenant-<industry>-<size>`), a logical-time
   epoch schedule (small: 1 epoch; medium: 2; large: 3 — `startedAt` offsets
   for the parameterizable runners), and a device-population scale (small
   10s, medium 100s, large 1000s — informational record fields, never fake
   telemetry).
3. **`src/adoption-run.ts`** — the deterministic adoption driver:
   - for each firm workspace, run the industry-applicable corpus subsets
     through the REAL runners (`runJourneyCorpus` with the firm's tenant id +
     epoch `startedAt` for field/commerce; `runJourney` loop for security);
   - repeatability: for ONE firm per industry (the large one), re-run the
     full applicable set and assert byte-identical outcomes (determinism
     proof — do NOT double-count re-runs in the journey-execution totals);
   - collect per-firm outcome sets as REAL runner outputs (never
     re-computed, never summarized away); expose per-firm execution counts.
   - **Count honesty law**: "100+ repeatable journeys per firm where
     supported" — where a firm's parameterizable corpora × epochs reach ≥100
     executions, assert it; where the security corpus's single-parameter
     shape or an industry's applicability mask leaves a firm below 100,
     record the exact shortfall + reason in the report's honest-counts
     ledger. NEVER inflate by counting re-runs.
4. **`src/incumbent.ts`** — incumbent capability baselines as DATA: per
   industry, the incumbent-vendor capability set (a realistic named-profile
   list — e.g. "incumbent-erp-suite", "incumbent-cmam", "incumbent-fsm",
   "incumbent-scm" — with per-capability coverage notes: what the incumbent
   does and does NOT do). Pure records; no vendor trademarks.
5. **`src/verdicts.ts`** — the adoption verdict rubric, DETERMINISTIC from
   the REAL outcomes + the incumbent baseline: compute per
   industry (and per firm) a `coverageRatio` = industry-applicable journeys
   PASSED / industry-applicable journeys TOTAL (never counting masked or
   unsupported ones as covered). Verdict thresholds (document them in code):
   - `SWITCH-ONLY` — coverageRatio = 1.0 AND every incumbent capability the
     industry needs is mapped to a passing journey family (full replacement);
   - `MAIN-INTERFACE` — coverageRatio ≥ 0.7 AND the core incumbent
     capabilities mapped (FleetOS becomes the primary interface);
   - `COMPLEMENT` — coverageRatio ≥ 0.3 (runs alongside the incumbent);
   - `RETAIN` — coverageRatio < 0.3 OR any critical journey FAILS honestly.
   A single honest failure must be visible in the verdict inputs (the
   report shows which journey failed and why — never hide it).
6. **`src/report.ts`** — the adoption report assembly: per-industry
   verdicts with their exact inputs (ratios, failing journeys), the
   30-workspace population table with per-firm execution counts, the
   honest-counts ledger, mobile-validation results per industry (assert
   the field corpus's mobile-shape journey is applicable + passing for every
   industry that has field applicability; industries without field
   applicability record that honestly), cross-role-handoff results (the
   handoff-family journeys per industry), incumbent-vs-FleetOS capability
   comparison per industry, and a FNV-1a-family digest + verify + tamper
   detection (copy the digest convention locally like the sibling packages).
7. **`src/index.ts`** — public barrel.
8. **Tests ≥ 50 net-new**: every industry's verdict computation (with
   fixture outcome sets); workspace population laws (10 industries × 3
   sizes = 30, unique ids, tenancy-scoped tenant ids); applicability masks
   well-formed; the driver's determinism (re-run byte-identity); count
   honesty (shortfall recorded, no inflation); mobile validation per
   industry; handoff chains; report digest + tamper (a tampered report
   must fail verify); negative fixtures (a failing critical journey must
   produce RETAIN, not a silent pass); the REAL-run integration test (run
   the full simulation over the REAL corpora once and assert the aggregate
   — journeys > 0, all deterministic, report verifies).
