Either bump the validator to accept `version: 2`, or roll the YAML back to `version: 1`. Without this, `pnpm architecture:check` is non-functional and cannot enforce layer/dependency/cycle rules — for any package, FleetOS or ZCode.

Suggested edge set (consistent with `spec/DEPENDENCY-GRAPH.md` canonical direction):

6. **`@fleetos/observations` uses `node:crypto` for SHA-256 digest computation.** This is a computational primitive (no I/O, no network, no process spawn) and is consistent with the A3 immutability + content-addressing law. The `scripts/architecture/policy.mjs` "domain-io" rule rejects `node:*` imports in domain layers — but that rule is currently scoped to managed modules only, and my packages are not yet registered (see delta #3). The TL should decide at F201 whether `node:crypto` (and similar computational primitives like `node:util`/`node:assert`) warrants a policy exception or whether the digest primitive should live in a shared utility module owned by the TL.
